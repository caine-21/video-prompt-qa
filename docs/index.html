关键发现
"A cinematic 4K aerial drone shot with bokeh, golden hour lighting, slow-motion, shallow depth of field."

这条提示词没有主体——却得了 8.4 / 10， 具体性维度评分 = 8。评估器被电影摄影术语迷惑了。 这个项目从提示词评估工具出发，最终成为一个研究 评估器可靠性的实验。

设计决策

为什么这样构建

→
5 个正交维度，而非单一总分
每个维度对应一种独立的失败模式。单一总分会掩盖问题所在——分维度评分迫使用户直面真正的根因，而不是靠猜。
→
所有模型共用同一套系统提示词
适配度分数必须有证据。每个模型的分数都要引用 prompt 中的主体、动作、镜头或时长约束，并明确指出缺口；它是推荐，不是实测生成成功率。
→
16 个边界用例 Fixtures，而非自动化测试
评估本质上是主观的。这些 Fixtures 定义了边界条件——系统在极端情况下必须得出正确结论。它们是规格说明，不是测试套件。
